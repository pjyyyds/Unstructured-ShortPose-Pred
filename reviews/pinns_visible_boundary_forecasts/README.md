# 四段真实道路边界的候选轨迹试点

`PROTOCOL.md` 固定主终点、界面支持、速度控制、后备规则、两图敏感性和真值穿线口径。`prepare_inputs.py` 从作者原始标签、四地原留地参数和冻结姿态缓存构建输入银行；只把观察序列送入预测器。局部图线来自两套预先保存的 AI 判读。每片是其地点的唯一代表，估计不含跨片、跨地点区间。

## 查看结果以前的实际检查

四片各 5、13、28、13 窗。第一套图仅 7 窗有支持，5 窗更换了概率首选。其中 1 窗在意大利，4 窗在日本，2 窗在泰国。第二套图仅日本 1 窗有支持，恰好是两套图共同支持的一窗，选中模式相同。两侧弧长不足使第一套 22 窗回退，其余 26 窗超过 5 m、4 窗当前图像锚点超出标定凸包。第一套支持窗中，历史运动与无向边界的夹角中位数 43.2°；六条候选的法向评分极差中位数为 0.143 m。第二套单窗对应 19.4°、0.268 m。完整计数和各片详情见 `blind/support.json`。这些数值未使用未来真值。

## 运行

在设置了项目源码与依赖的 Python 环境中，可按下列调用顺序重建。前两条处理私有原料，第三条在真实资料上只检查历史输入与选中模式。合成单测含5、13、28、13窗的四片数据，用来检验等权聚合、缺少支持后的回退、穿过边界仍可被选中、相同分数的决胜条件及零分母。

```sh
python prepare_inputs.py "$PINNS_METADATA" "$HELDOUT_ARTIFACTS" "$ANNOTATIONS" .
python test_visible_boundaries.py
python evaluate_visible_boundaries.py . blind
python build_kaggle_cell.py
```

生成的 `kaggle_cell.py` 可在私有 Kaggle CPU 作业直接运行。内嵌的是压缩数值数组和源程序，不含照片和视频。单元先生成全部逐窗选择，核对锁定的摘要，再解封目标，通过相同规则复计并输出 `/kaggle/working/visible_boundary_forecasts.zip`。输出包内含私有逐窗选择，公开以聚合 JSON、协议和程序为限。将 `observed_and_candidates.npz`、`sealed_targets.npz`、`blind/private_selected_modes.json` 和生成的私有 Kaggle 单元保留在研究工作区。

59 窗继承了先前四地队列要求未来 30 个位置均有标注的纳入条件。模型和重排没有使用这些未来位置来作选择；样本覆盖仍然偏向可持续跟踪的人。第一套描线是主分析，第二套读数只在一个窗口提供相同的局部支持。即使四片等权的平均误差出现变化，其来源也局限于实际换了候选的少数窗口。不能将有支持的几何结果外推到所有路缘、未观察到的场景，或被遮挡初现的行人。
