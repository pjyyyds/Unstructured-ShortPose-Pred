# 五帧图输入的速度回看边界

五个 10 Hz 观测是 t₀−4 至 t₀，所以两次观测最多相隔四步。历史构建器在前四步都缺少同一对象时，还会查询 t₀−5。当前构建器将目标和邻居的速度搜索限制在前四步。缺少可用前点时，保留当前邻居，速度有效位、相对速度与径向速度置零；行人类型仍沿用当前标签或有效速度低于 0.20 m/s 的既有规则。[正式构建器](../../../src/data/pinns_extractor.py) · [合成边界测试](../../../tests/test_pinns_graph_history.py)

按47片原生标签的 `1+3t` 帧重建。60,186 条行人状态中，59,729 条最近前点在 t−1，457 条在前五步均无前点。15,874 条车辆状态的对应计数为15,685和189。仅在 t−2、t−3、t−4 或 t−5 才重新出现的记录均为零。项目的既有核查验证了原测试集和四地点留出窗口的目标类型；本次补查全部历史窗口及邻居边。[既有目标类型核查](../../../results/pinns_type_input_audit.json)

原7,283窗里，当前目标五帧内有2、3、4、5个地面观测的分别为35、53、53、7,142窗。修复前后对每窗的目标类型、邻居掩码、邻居类型和全部九个边通道进行逐值对照。所有真实边的逐通道差的最小值和最大值均为0。在原训练／验证的302个窗口里，旧程序会查询额外一帧有无邻人记录，结果全部为空。原测试497个窗口的自身位置都有完整五帧。槽数在每次作为目标的邻域中分别计数。[全部汇总与逐地点计数](summary.json)

四地点留出的 M0/M1 输入包含目标类型，两者的实际前向均不接收邻边。另有单独的四地点人车图试验，它已从五个历史快照建立邻边。对该试验，将真实图输入与假设允许第六个快照的输入逐值比较。额外的历史位置在37个缺前点的槽中均不存在。全部1,482窗的边、类型、掩码、邻人身份、来源类别和速度间隔与实际 Kaggle 返回文件逐项一致。仅从返包读取图输入和身份，未读取预测路径、计算预测误差或重新训练。[人车图试验](../RESULTS.md)

## 复核

在仓库根目录运行下列命令。首项使用合成数据即可。稀疏邻人在第五个前序时刻有位置时，现行实现会丢弃那次观测；在第四个前序时刻有位置时，现行实现仍计算速度。两个用例都调用实际窗口构建器。第二项需要原标注与标定、原因果地图缓存的 `maps.npz`、原四地点姿态包和人车图返包，以校验实际窗口键、分割和张量。输入文件保持所示参数顺序。

```sh
python -m unittest -v tests.test_pinns_graph_history
python reviews/pinns_graph_control/history/audit.py METADATA_ROOT ORIGINAL_MAPS.npz shortpose_heldout.zip pinns_graph_control.zip history_summary.json
```

程序默认从本地 Git 历史读取提交 `c5344f1e5c1efea657381f7d2e6d4e74dd1db977` 的原构建器，严格校验源文件 SHA-256 后直接调用历史函数，再调用正式修复函数。同窗对照允许新版本额外返回 `person_id` 元数据，独立核对该字段与历史几何恢复的身份一致。浅检出可通过 `--prior-extractor ARCHIVED_EXTRACTOR.py` 显式传入相同 SHA 的原文件。重放沿用历史入组规则对未来标注可用性的检查；任何未来坐标都不进入邻居状态或速度计算。[重放程序](audit.py)
