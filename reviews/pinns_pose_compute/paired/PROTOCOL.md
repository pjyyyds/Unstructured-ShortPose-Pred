# 同一批行人的姿态图乘法与配对前向耗时

本方案在看到真实同步输入的两种执行结果和耗时之前固定。原路径 A 使用已训练的 PINNS T5 Full seed 42，部署路径 B 仅将三个 ST-GCN 块中无偏置的邻居通道扩展移到关节聚合之后，即从 A(HW) 改为 (AH)W。此处公式中的 A 是图邻接矩阵。两路均使用 eager 顶层及原先脚本化的内部循环，加载的全部 161 个状态项和全部命名缓冲区须逐值相同。计时之前构建 B。默认模型、训练、旧计时结果各自保留。

## 固定输入与数值检查

直接复用已经核对过的私有输入文件 `pinns_sync_latency_private.bin`（SHA-256 `362efbaa576340495749b0820f398d768b82e000e714492265b91183ef061873`）。新 notebook 只内嵌代码。其优化模块 SHA-256 为 `3059a50208a07b76294f763f500c1043fce638b4902657380e9a6aa5188bfe23`。旧输入中含原计时脚本（SHA-256 `5de7c4993380ced7341bc04e4667a51fb7d4d81ce12c5296dac4e7b8df464e61`）、模型源码和真实权重。新入口复用旧入口的逐文件哈希、源模型载入和同刻人员排序。

- 选用美国、日本各一个实景镜头的单一决策时刻，各 12 人，有 100 和 124 条入选行人邻边。两处都无入选车辆。T=5/10/20、N=1…12，共 72 个场景负载、36 种形状。每个时刻按 ID 升序取前 N 人，所有输入直接复用。共有 468 次重叠的行人输出、2,808 条 30 步候选轨迹，原始独立人次为 24。全部时长使用同一 T5 权重。
- 逐项比对所有六候选在每步的两个坐标、全部模态与五动作的概率和 logits、质量门与邻居注意力。每一坐标的绝对容差为 0.0002 m，其余各标量的绝对容差均为 0.00002；相对容差为零。保存非有限数、精确偏差数、超界数与最大差。数值接近也可能改变决策，单独保留最高概率的模式变化、六候选完整顺序变化、全部 15 对的相对次序变化，以及五个动作按 0.5 阈值的变化数。概率完全相等时取较小索引；预定近并列为原始被翻转的两个候选概率之差不超过 0.00004（两候选各可变动 0.00002）。同时记录两路前两名精确或近并列的频数。近并列解释与是否翻转分别报告。
- 每格预热后额外做 A/B/A/B 四次未计时前向，两路各自重复用于观察运行内波动。每次前向的全部输出存于私有数组；结构异常、容差以外的差异或顺序翻转在汇总中保留。如果有超界或离散变化，应连同影响范围解释该负载的性能比较。
- 所有输入和权重预先移到同一真实 CUDA 设备。固定 FP32，关闭 matmul/cuDNN TF32 和 cuDNN benchmark。预热每路各 25 次。每格用固定随机种子将 50 个 AB、50 个 BA 配对打乱。每个前向单独执行 CUDA 前同步和后同步，测主机墙钟，从前同步之后计至后同步返回；不含 H2D、姿态提取、图构造、输出复制和首次加载。保留全部配对原始毫秒值、先后顺序、两路均值/中位数/P95，以及分顺序的配对中位差。
- **主要时延比较**只取 T=20、N=12。每个时刻取 100 对“原始减优化”毫秒差的中位数，再算两时刻等权平均；百分比对每对计算 100 × (原始−优化)/原始，同样先取场内中位数再等权。正值表示优化路径更快。其余负载为描述。100 个计时对反映同一场景和进程中的测量波动，不能替代场景复现。只给出实际设备身份；RTX 4090、Jetson Orin NX 的目标需要分别在对应实机验证。
- `paired_report.json` 为可复查的聚合、原始计时及环境记录。`private_outputs.npz` 是按时刻和稳定行号排列的完整模型输出，仅供私下核对。公开时仅使用聚合报告。无需预测标签或重新拟合。

## 运行

Kaggle 私有 Notebook 选择 GPU，附加已存在的 `pinns_sync_latency_private.bin`，导入配对 notebook 并运行全部单元。Internet 可关闭。产物在 `/kaggle/working/pinns_paired_pose_compute.zip`。使用同样软件环境的其他真实 CUDA 台架也可显式指定挂载目录和固定源码。

```sh
python paired_pose_compute.py --input-root /path/to/private-mount --transform /path/to/src/models/pose_inference.py --output /path/to/new-results.zip
```

独立单测使用合成分数、模拟同步计时器和随机人体特征。若需运行实际模型结构的合成测试，设置 `SHORTPOSE_REPO` 指向含模型、部署模块和权重的项目检出，`SHORTPOSE_LATENCY_RUNNER` 指向已冻结的 `measure_latency.py`。

```sh
SHORTPOSE_REPO=/path/to/repo SHORTPOSE_LATENCY_RUNNER=/path/to/measure_latency.py python -m unittest -v test_paired_pose_compute
```
